ENGINEERING CASE STUDY / 01

Salesforce CRM Wizards.

Guided, metadata-driven record entry on Salesforce.

Open-source reference · Apex · Lightning Web Components · Custom Metadata
THE CONTEXT

What I set out to solve.

Patterns from enterprise CRM work, rewritten as a neutral open-source reference for B2B CRM. Users need a guided way to create Contacts and Opportunities that keeps data clean: find existing people before creating new ones, merge what is duplicated and capture products in one consistent step.

THE ENGINEERING QUESTION

Configure, don't recode.

How can administrators change record types, fields, steps, labels and duplicate-match rules without a code deployment, while the wizard still enforces data quality and security?

CONTACT WIZARD

Find before you create.

A search-as-you-type identify step scores possible matches across Contacts and unconverted Leads with weighted, configurable rules. It also works with Shield Platform Encryption, using exact matches and case variants only.

A field-by-field review merges up to three Contacts and converts the chosen Leads into the kept Contact. Account suggestions come from the Lead company, related accounts use AccountContactRelation, and duplicate rules are handled with “save anyway” or merge with the existing record.

OPPORTUNITY + PRODUCTS WIZARD

One step, one transaction.

The wizard picks a country-specific price book with a fallback, then captures products with per-line attributes and saves everything in a single transaction.

Writes run in system mode, but only for fields on a metadata whitelist. Users without Create permission can still work through a governed UI, without being given broad access.

INTEGRATION-READY SYNC PATTERN

Ready to plug in.

An integration-ready sync pattern demonstrated with mock data: a source interface with a mock implementation that reads sample JSON from a static resource. A real API adapter plugs into the same interface.

Queueable and Schedulable Apex run an incremental sync with a watermark, and records are upserted on an external ID so repeated runs stay consistent. The reference makes no external calls and holds no credentials.

BULK-SAFE FLOW PATTERNS

Built for volume.

Flows keep queries out of loops, and team rebuilds are idempotent: running them again gives the same result instead of duplicating records.

ENGINEERING PRACTICES

Built to be handed over.

Apex tests, header comments for future maintainers and AI-assisted handover, check-only deployment validation before production, and everything deployable to a Salesforce Developer Edition org.
